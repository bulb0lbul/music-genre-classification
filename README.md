# Music Genre Classification

Учебный проект по определению музыкальных жанров на основе
мел-спектрограмм аудиозаписей. Планируется реализация на Python
с использованием свёрточной нейронной сети (CNN).

## Статус

Проект находится на этапе планирования. Исходная формулировка темы
хранится в `task.txt`. Обработка данных, модель и обучение пока не реализованы.
Датасет ещё не загружен; результатов экспериментов пока нет.

## Датасет

Рассматриваются два поднабора Free Music Archive (FMA):

| Поднабор | Аудиозаписи | Жанры | Баланс классов | Размер архива |
| --- | --- | --- | --- | --- |
| FMA small | 8 000 | 8 | Сбалансированы | 7,2 GiB |
| FMA medium | 25 000 | 16 | Несбалансированы | 22 GiB |

В обоих поднаборах используются фрагменты длительностью 30 секунд.
Для первой версии предварительно выбран **FMA small**, чтобы сократить
время обработки и обучения. Окончательный выбор зависит от требований
к проекту и доступных вычислительных ресурсов.
Кроме аудиофайлов понадобятся метаданные из `fma_metadata.zip`.

Описание и ссылки на данные:
[официальный репозиторий FMA](https://github.com/mdeff/fma).
Аудиозаписи распространяются под лицензиями отдельных треков;
датасет не включается в этот репозиторий.

## План реализации

Каждый самостоятельный блок будет размещён в отдельном Python-файле.
Имена ниже описывают планируемую структуру: этих файлов пока нет.

| Файл | Назначение |
| --- | --- |
| `config.py` | Общие пути и параметры обработки и обучения |
| `prepare_data.py` | Чтение метаданных, выбор поднабора и сопоставление файлов с жанрами |
| `analyze_data.py` | Проверка аудио и анализ распределения жанров |
| `split_data.py` | Подготовка train/validation/test и проверка пересечений |
| `extract_spectrograms.py` | Получение и сохранение log-mel-спектрограмм |
| `dataset.py` | Загрузка примеров для нейросети и аугментации |
| `baseline.py` | Простая модель для сравнения с CNN |
| `model.py` | Архитектура CNN |
| `train.py` | Обучение и выбор модели по validation |
| `evaluate.py` | Итоговая оценка на test |
| `visualize.py` | Графики обучения, спектрограммы и матрица ошибок |
| `predict.py` | Определение жанра нового аудиофайла |

Дополнительно планируются `requirements.txt` со списком зависимостей
и `colab.ipynb` для запуска этапов в среде Google Colab.

## Порядок работы с данными

1. Загрузить аудио и метаданные, сформировать список записей выбранного поднабора.
2. Проверить аудиофайлы, сохранить список исключённых записей и причины исключения.
3. Подготовить выборки на основе официального разделения FMA;
   проверить пересечения записей и исполнителей между выборками.
4. Привести аудио к общим параметрам и вычислить log-mel-спектрограммы.
5. Обучить простую модель для сравнения, затем CNN.
6. Подобрать параметры и выбрать модель по validation.
7. Оценить итоговый вариант на test и разобрать ошибки по жанрам.

Если записи нарезаются на фрагменты, все фрагменты одной записи
должны оставаться в одной выборке. Статистики нормализации вычисляются
только на train; аугментации применяются только к train.
При использовании фрагментов итоговые предсказания агрегируются по записи.

Планируемые метрики: accuracy, macro-F1, precision/recall/F1 по жанрам
и матрица ошибок. Для воспроизводимости будут сохраняться seed,
списки записей, соответствие меток жанрам и параметры экспериментов.

## Среда разработки

Код планируется редактировать в VS Code и хранить в GitHub.
Обучение можно будет выполнять локально или в Google Colab;
среда обучения пока не выбрана.

При работе с Colab код будет загружаться из GitHub.
Изменения локальных файлов не попадают на сервер Colab автоматически:
сначала их нужно отправить в GitHub, затем обновить копию на сервере.
Данные и результаты необходимо сохранять за пределами временного диска Colab.

## Хранение файлов

Планируемые папки:

- `data/` — исходные данные и подготовленные массивы.
- `artifacts/` — обученные модели и настройки экспериментов.
- `reports/` — таблицы метрик, графики и журналы проверок.

Их содержимое исключено из Git через `.gitignore`, кроме служебных
файлов `.gitkeep`, которые при необходимости позволят сохранить пустые папки.
Код, инструкции и выбранные итоговые иллюстрации можно хранить в репозитории;
для иллюстраций следует использовать отдельную отслеживаемую папку.

Команды установки зависимостей и запуска будут добавлены после реализации
первых блоков и проверки выбранной среды.
