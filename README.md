# Music Genre Classification

Определение музыкального жанра по мел-спектрограмме аудиозаписи.

## Текущее состояние

Подготовлены загрузка датасета, обработка метаданных, проверка аудио и анализ результатов. Из 8 000 записей FMA small оставлено 7 944. Аудио хранится только в исходных MP3. При загрузке запись переводится в моно, приводится к 44 100 Гц и обрезается с начала до минимальной длины: 1 321 438 отсчётов, примерно 29,96458 с. Промежуточные WAV не создаются. Исходные частоты, каналы и факт ресемплинга сохраняются в таблицах.

## Датасет

Используется **FMA small**: 8 000 фрагментов примерно по 30 секунд, 8 жанров. Архив аудио занимает около 7,2 GiB, метаданных — 342 MiB.

Описание и ссылки на скачивание: [официальный репозиторий FMA](https://github.com/mdeff/fma#data). Нужны `fma_small.zip` и `fma_metadata.zip`.

## Установка

Проверено на Python 3.12 и macOS с Apple Silicon.

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

Для следующих запусков достаточно активировать существующее окружение:

```bash
source .venv/bin/activate
```

## Порядок запуска

Весь процесс одной командой:

```bash
python3 run_pipeline.py
```

Скачанные аудио и метаданные используются повторно, недостающие части скачиваются автоматически. Далее последовательно выполняются восемь этапов: подготовка метаданных, проверка аудио, перевод в моно, приведение к 44 100 Гц, подготовка фрагментов минимальной длины с обрезкой при загрузке, проверка примеров с подготовкой прослушивания, анализ результатов и построение всех графиков. При ошибке процесс останавливается. Таблицы и отчёты обновляются при каждом запуске; аудио обрабатывается в памяти при чтении исходных MP3. В общем запуске графики строятся один раз в конце. При отдельном запуске этапов их графики создаются автоматически; отключить их можно флагом `--no-plots`.

Отдельные этапы:

```bash
python3 download_data.py
python3 prepare_data.py
python3 validate_audio.py
python3 process_audio.py --all
python3 resample_audio.py
python3 trim_audio.py
python3 check_audio.py
python3 analyze_data.py
python3 plot_data.py
```

Если данные уже скачаны, первую команду можно пропустить. Для отдельной загрузки: `python3 download_data.py --only metadata` или `python3 download_data.py --only audio`.

## Графики обработки

Графики создаются автоматически при запуске этапов:

- `plots/metadata_overview.png` — исходные жанры и выборки.
- `plots/audio_validation.png` — итоги очистки, причины исключений и потери по жанрам.
- `plots/mono/mono_overview.png` — число каналов до/после и изменение уровня на выбранных примерах.
- `plots/mono/track_*.png` — исходные каналы, моно и RMS-уровень по времени для примеров разных форматов.
- `plots/random_waveforms.png` — амплитуда трёх случайных монофайлов на всей длительности.
- `plots/overview.png` — общий анализ очищенного набора.
- `plots/audio_check/track_*.png` — RMS-огибающие и одинаковый активный фрагмент до/после обработки для проверочных записей.
- `plots/trimming_examples.png` — конец записей до/после обрезки с выделенным удаляемым участком.
- `plots/genre_examples.png` — специально подобранные различающиеся записи восьми жанров; масштаб каждой волны приведён к её пику только на рисунке.
- `plots/sample_rates.png` — распределение исходных частот и один фрагмент при 22 050, 44 100 и 48 000 Гц; пересчёт только для рисунка.
- `plots/mono/origin_*.png` — три жанра; на каждом рисунке одно исходное моно и три различающихся моно из стерео того же жанра.

Одиночный запуск `python3 process_audio.py путь_к_аудио` тоже сохраняет график сравнения. RMS характеризует уровень сигнала, а не качество распознавания.

Перестроить все графики без повторной обработки аудио: `python3 plot_data.py`. Построить звуковые волны отдельно: `python3 plot_data.py --kind waveforms`. При каждом запуске выбираются три случайные записи. Для повторяемого выбора: `python3 plot_data.py --kind waveforms --seed 42`. Все изображения сохраняются в `plots/`.

Построить сравнения отдельно: `python3 plot_data.py --kind examples`. Для выбора примеров жанров используются только записи train: сравниваются паузы, динамика и форма огибающей на небольшом наборе кандидатов. Эти иллюстрации не описывают жанры в целом. Общие графики лежат прямо в `plots/`, серия сравнений каналов — в `plots/mono/`.

## Ресемплинг до 44 100 Гц

`python3 resample_audio.py` читает `data/processed/tracks_mono.csv` и записывает параметры обработки в `data/processed/tracks_resampled.csv`. Для фактического чтения используются `load_mono_audio` и `load_resampled_audio`: исходный MP3 декодируется в память, каналы усредняются, затем при необходимости выполняется `librosa.resample` с методом `soxr_hq`. WAV-файлы не сохраняются.

Из 7 944 записей пересчёт требуется для 419: 11 с 22 050 Гц и 408 с 48 000 Гц. Для остальных 7 525 частота уже равна 44 100 Гц.

В таблице сохраняются жанр, метка, выборка и исполнитель, а также происхождение обработки:

- `source_audio_path`, `audio_path` — путь к исходному MP3.
- `source_channels`, `channels` — число каналов до и после сведения в моно.
- `source_sample_rate`, `sample_rate` — частота до и после.
- `was_resampled` — `True` для пересчитанных записей и `False` для исходных 44 100 Гц.
- `source_frames`, `frames` — число отсчётов до и после ресемплинга.
- `source_duration_seconds`, `duration_seconds`, `duration_delta_seconds` — длительность до, после и её изменение.
- `resample_method` — `soxr_hq` или `unchanged`.

Эти столбцы позволяют позже сравнить записи по исходной частоте и факту ресемплинга. Проверяются частота 44 100 Гц, один канал и ожидаемое число отсчётов. Округление числа отсчётов даёт изменение длительности меньше одного отсчёта целевой частоты.

Примеры ресемплинга для каждого исходного формата сохраняются в `plots/resampling/`. На примерах показаны только исходные и итоговые отсчёты одного фрагмента длительностью 2 мс. Перестроить только графики: `python3 plot_data.py --kind resampling`.

Повышение частоты 11 исходных записей с 22 050 до 44 100 Гц не восстанавливает отсутствующие высокие частоты. Их происхождение сохранено в таблице для дальнейшего анализа.

Сравнения происхождения моно можно построить отдельно: `python3 plot_data.py --kind mono-origins`. Берутся три жанра с наибольшим числом исходных моно в train; исходная частота всех сравниваемых записей — 44 100 Гц. Из участка 10–10,2 с каждой записи выбирается наиболее энергичный фрагмент 40 мс. Три записи из стерео подбираются из всех доступных кандидатов этого жанра последовательно по наибольшему минимальному расстоянию до уже выбранных примеров: сравниваются доли энергии в частотных полосах, смены знака, RMS относительно пика и огибающая. Это подбор различающихся форм, а не доказательство влияния сведения каналов.

На каждом рисунке четыре графика друг под другом: сверху исходное моно, ниже три записи того же жанра, переведённые из стерео в моно. Время и амплитуда имеют общий масштаб; значения амплитуды не нормируются. Аудиофайлы не меняются. ID, исходное число каналов, начала фрагментов и расстояния до исходного моно сохраняются в `reports/mono/origin_comparisons.csv`.

## Единая длина сигнала

`python3 trim_audio.py` читает `data/processed/tracks_resampled.csv`, выбирает минимальное число отсчётов и сохраняет правила чтения фрагментов в `data/processed/tracks_trimmed.csv`. Для текущего набора это 1 321 438 отсчётов при 44 100 Гц, то есть 29,96458050 с. Функция `load_trimmed_audio` загружает исходный MP3, усредняет каналы, при необходимости выполняет ресемплинг до 44 100 Гц и возвращает первые 1 321 438 отсчётов. Обрезка не меняет частоту и скорость воспроизведения; нули не добавляются.

Отдельные WAV-копии не создаются. В `audio_path` остаётся путь к исходному MP3. Параметры исходного файла могут отличаться от параметров возвращаемого массива. Столбцы `frames` и `duration_seconds` описывают фрагмент, который возвращает `load_trimmed_audio`. Для дальнейшей обработки аудио нужно читать через эту функцию:

```python
from pathlib import Path
import pandas as pd
from trim_audio import load_trimmed_audio

row = pd.read_csv("data/processed/tracks_trimmed.csv").iloc[0]
audio, sample_rate = load_trimmed_audio(Path("data") / row.audio_path, int(row.frames))
```

Таблица сохраняет жанры, выборки и происхождение ресемплинга. `pre_trim_audio_path` указывает на исходный MP3, `frames_before_trim` и `duration_before_trim_seconds` — длину массива после сведения в моно и ресемплинга, до обрезки, `cropped_frames` и `was_trimmed` — сколько отсчётов исключается из фрагмента и требуется ли обрезка. Границы фрагмента — `trim_start_frame = 0` и `trim_end_frame`.

`plots/trimming_examples.png` показывает концы трёх записей разной исходной длины. Нулевая точка — граница обрезки; справа выделен хвост, который не входит в готовый фрагмент. Перестроить только этот рисунок: `python3 plot_data.py --kind trimming`.

## Проверка обработки примеров

```bash
python3 check_audio.py
open reports/audio_check/index.html
```

Проверяются пять записей: все сочетания исходной частоты и числа каналов, самая короткая и самая длинная запись. Скрипт сверяет исходные параметры с таблицей, итоговую форму массива, частоту 44 100 Гц, отсутствие нечисловых значений и тишины. Проверяется сохранение длительности до обрезки с точностью до одного отсчёта и точное совпадение результата с началом массива после ресемплинга. RMS-огибающие сравниваются на общей шкале времени; их корреляция выводится как дополнительный показатель.

Результаты сохраняются в `reports/audio_check/examples.csv`, пары пятисекундных фрагментов для прослушивания встроены в `reports/audio_check/index.html`. У фрагментов одинаковые временные границы; исходное стерео сохраняется. Для предотвращения перегрузки в плеере обоим фрагментам пары при необходимости применяется один коэффициент громкости. Рабочие массивы остаются без этого изменения. Полные WAV-копии не создаются.

Графики находятся в `plots/audio_check/`. Перестроить только их: `python3 plot_data.py --kind audio-check`. На слух нужно сравнить темп, высоту звука и отсутствие искажений; автоматический отчёт не отмечает прослушивание выполненным.
