# Music Genre Classification

Учебный проект по определению музыкальных жанров на основе
мел-спектрограмм аудиозаписей. Реализация на Python; для классификации
планируется использовать свёрточную нейронную сеть (CNN) на PyTorch.

## Текущее состояние

- Подготовлено локальное окружение `.venv` на Python 3.12.
- Установлены библиотеки для обработки аудио, анализа данных,
  визуализации и обучения. Проверенные версии указаны в `requirements.txt`.
- На искусственном сигнале проверены построение мел-спектрограммы,
  сохранение графика и вычисление градиентов в PyTorch.
- PyTorch обнаруживает ускорение Apple MPS; обучение модели на нём
  ещё не проверялось.
- В `data/` размещены распакованные метаданные FMA и 8 000 MP3-файлов
  из FMA small. Наличие файлов проверено; полная проверка читаемости
  аудиозаписей ещё не выполнялась.
- Добавлен локальный скрипт `download_data.py` для загрузки FMA small
  и метаданных; проверен на тестовых архивах. Работа выполняется локально.

Подготовка таблицы записей, анализ аудио, получение спектрограмм всего
датасета, модель и обучение пока не реализованы. Метрик качества пока нет.
Общая конфигурация не создавалась: структура проекта будет уточняться
по мере реализации отдельных этапов.

## Датасет

Для первой версии используется **FMA small**: 8 000 записей,
8 сбалансированных музыкальных жанров, фрагменты длительностью 30 секунд.
Размер архива аудио — около 7,2 GiB.

**Источник, описание и ссылки на скачивание:**
[официальный репозиторий FMA — раздел Data](https://github.com/mdeff/fma#data).

Необходимые архивы:

- `fma_small.zip` — аудиозаписи выбранного поднабора.
- `fma_metadata.zip` — метаданные всего FMA; нужные записи предстоит
  выбрать по принадлежности к поднабору small.

Основные таблицы метаданных: `tracks.csv` со сведениями о записях
и `genres.csv` со справочником жанров.

В исходной задаче также рассматривался FMA medium: 25 000 записей
и 16 несбалансированных жанров. Для текущей работы выбран FMA small.
Аудиозаписи распространяются под лицензиями отдельных треков;
датасет в Git-репозиторий не включается.

## Локальная среда

Разработка и запуск выполняются на компьютере, код хранится в GitHub.
В терминале из папки проекта:

```bash
source .venv/bin/activate
python3 --version
python3 -m pip check
```

Для создания окружения на другой машине:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

Зависимости проверены на macOS с Apple Silicon и Python 3.12.
Совместимость с другими средами отдельно не проверялась.

## Загрузка данных

Данные можно скачать вручную по ссылкам в [официальном репозитории FMA](https://github.com/mdeff/fma#data) или запустить из папки проекта:

```bash
python3 download_data.py
```

По умолчанию скрипт скачивает архивы **FMA small и метаданных**,
проверяет их SHA-1 и распаковывает в `data/` рядом со скриптом.
Для загрузки нужна только стандартная библиотека Python.
Архив аудио занимает около 7,2 GiB, метаданных — около 342 MiB;
под скачивание и распаковку рекомендуется иметь не менее 20 GiB свободного места.
Архивы сохраняются в `data/`. Из метаданных извлекаются только
`tracks.csv` и `genres.csv`.

Отдельная загрузка метаданных или аудио:

```bash
python3 download_data.py --only metadata
python3 download_data.py --only audio
```

Другую папку можно выбрать через `--data-dir /путь/к/данным`.
Если нужные распакованные файлы уже присутствуют и имеют ненулевой размер,
скрипт пропускает скачивание. Для аудио дополнительно проверяется наличие
8 000 MP3-файлов. Эта проверка не подтверждает читаемость или целостность
уже распакованных файлов. Неполные папки не перезаписываются:
скрипт сообщает о проблеме и останавливается.
Прерванная загрузка при следующем запуске начинается заново.

## Ближайшие этапы

1. Прочитать метаданные и выбрать записи FMA small.
2. Сопоставить ID записей, жанры и пути к аудиофайлам.
3. Проверить аудио и сохранить причины исключения проблемных записей.
4. Изучить распределение жанров и официальное разделение на выборки;
   проверить пересечения записей и исполнителей.
5. Разработать и проверить получение log-mel-спектрограммы одной записи.
6. Применить проверенную обработку ко всему выбранному набору.
7. Реализовать простую модель для сравнения, затем CNN, обучение и оценку.

Каждый самостоятельный блок будет реализовываться в отдельном Python-файле.
Имена и состав следующих файлов будут определяться по мере работы.
Модель будет выбираться по validation, а итоговое качество оцениваться
на test с помощью accuracy, macro-F1 и показателей по жанрам.
